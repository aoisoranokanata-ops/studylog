# StudyLog 子機（ブラウザアプリ）制作指示

## 0. 進め方
- 最初に `spec/transfer-spec.md` を読むこと。転送に関わる部分はすべて本書より仕様書を優先する。
- いきなり実装しない。まず**ディレクトリ構成、IndexedDBの構造、フェーズ1の実装計画**を提示して承認を得ること。
- 不明点は推測で埋めず、質問するか代替案を出すこと。
- **機能を増やしすぎないこと。** 集計・分析・計画は母艦の役割であり、子機には実装しない。

## 1. 位置づけ
外出先（図書館など）で使う、薄い**子機**アプリ。
- 母艦から「今日のノルマ」を受け取る
- 勉強時間を計測し、メモ・範囲・正答数・誤答を記録する
- 記録を母艦に送る
- データは一時的なもの。取り込み済みの記録は7日間だけ履歴として表示し、その後に削除する

## 2. 技術要件
- 素のHTML / CSS / JavaScript（ES Modules）。**ビルド工程なし**
- GitHub Pagesで公開する。リポジトリの `web/` フォルダを GitHub Actions でデプロイする（ワークフローも作成すること）
- PWA：manifest と Service Worker によるオフライン動作、ホーム画面への追加。Service Workerのキャッシュにはバージョン番号を付け、更新時に「新しいバージョンがあります」と表示して再読み込みを促す
- データ保存：IndexedDB（薄いラッパーを自作）。起動時に `navigator.storage.persist()` を要求する
- QRコードの読み取り：**jsQR を `web/vendor/` に同梱する**（iOSのSafariは BarcodeDetector API に対応していないため）。カメラは `getUserMedia`（背面カメラを優先）
- 圧縮・展開：`DecompressionStream('deflate-raw')`
- 外部CDNは使わない。外部への通信は一切行わない
- スマホ縦向き（360px〜）を最優先に設計し、タブレットにも対応する。ダークモードに対応する
- 日本語UI
- 対象：最新版の iOS Safari（ホーム画面に追加したPWAを含む）、Android Chrome、PCのChrome・Edge

### 注意事項（iOS）
- ホーム画面に追加したPWAと、Safariで開いたページは**保存領域が別**である。初回案内で「ホーム画面に追加してから使う」よう促すこと
- 画面ロック中はJSが止まる。計測は必ず時刻の差分で計算すること

## 3. データ（IndexedDB）
- `inbound`：最後に受け取った下りパッケージの内容（masters、quotas、reviews、summary、settings、packageId）
- `sessions`、`mistakes`、`reviewResults`、`quotaStatus`：転送仕様書の上りの項目と同じ。各レコードに状態（`pending`：未取り込み／`acked`：取り込み済み、とその日時）を持たせる
- `outbox`：送信した上りパッケージごとの `packageId`、`includedIds`、送信時刻
- `timer`：計測中の状態（開始時刻、一時停止の区間、選択中のノルマ・資格・参考書・分野）
- `device`：deviceId（初回起動時に生成）、表示名（例：iPhone。変更可能）

## 4. 画面と機能

### 4.1 今日（ホーム）
- 試験日までのカウントダウン（`summary`）
- 今日のノルマ一覧：目標時間、そのノルマの実績時間（子機で記録した分）、達成状況（未着手／一部／完了／スキップ）。タップするとそのノルマで計測を開始する
- 今週の勉強時間と目標（母艦から受け取った値＋子機で未送信の記録の時間）
- 今日の復習対象の件数
- 警告バナー：未取り込みの記録が3日以上前からある、受け取ったノルマの日付が古い、のいずれかの場合

### 4.2 計測
- ストップウォッチ方式（開始／一時停止／再開／終了）。経過時間は開始・一時停止の時刻から計算する。状態を随時保存し、リロードやアプリを閉じた後でも復帰すること
- ノルマを選ばずに「自由記録」でも開始できる。この場合は、受け取った資格・参考書・分野の一覧から選ぶか、「未分類」を選ぶ
- 計測が5時間を超えた場合は、終了時に「つけっぱなしではないか」と確認し、終了時刻を修正できるようにする
- Screen Wake Lock に対応している環境では、画面消灯の防止をオプションとして提供する
- **終了操作は最短2タップで保存まで完了できること**：終了 → 確認シート（範囲、正答数、集中度、メモ、ノルマの達成状況はすべて任意）→ 保存
- 確認シートから、そのまま誤答の登録（4.3）に進める

### 4.3 誤答の簡易登録
- 入力項目は、問題の識別（例：p.52 問3）と一言メモだけを必須にする。誤答理由は任意の選択肢
- 直前の記録の資格・参考書・分野を自動で引き継ぐ
- 続けて何件でも登録できること

### 4.4 復習（フェーズ3）
- 受け取った `reviews` を1件ずつ表示し、「できた／できなかった」を記録する（`reviewResults`）

### 4.5 手動記録と履歴
- 時間を後から手動で記録する
- 履歴：未取り込みの記録（編集・取り消しが可能）と、取り込み済みの記録（閲覧のみ。7日間表示）を分けて表示する
- 未取り込みの記録を取り消した場合、一度も送信していなければ物理削除し、送信済みなら `deleted: true` にする

### 4.6 転送
- **受け取る**（下り）：
  - QRコードを読み取る（カメラ）
  - ファイルを選ぶ（`<input type="file" accept=".json">`。iOSではファイルアプリ経由でGoogleドライブの `outbox/` から選べる）
  - 文字列を貼り付ける（`SL1:` で始まるもの）
  - 受け取った内容の要約（ノルマ何件、復習何件、取り込み済みになった記録何件）を表示する
- **送る**（上り）：
  - 未取り込みの記録をすべて含む上りパッケージを作成する（累積送信）
  - Web Share API でファイルの共有に対応している環境では共有シートを出す（Googleドライブの `StudyLog/inbox/` に保存してもらう）。非対応ならダウンロードする
  - 送信後、`outbox` に記録する。未取り込みの件数と最終送信日時を表示する
- 取り込み済み通知（`acks`）の処理と、7日を過ぎた記録の削除は、転送仕様書の第5章のとおりに行う

### 4.7 設定
- 端末の表示名、Wake Lock、テーマ
- データの全削除（未取り込みの記録がある場合は強く警告し、2段階で確認する）
- アプリのバージョンと、対応している `schemaVersion` の表示

## 5. 非機能要件
- 初回の読み込み後は完全にオフラインで動作すること
- JavaScriptの合計（jsQRを除く）を、目安として100KB以下に抑えること
- ボタンのタップ領域は44px以上
- 日付の計算は、下りパッケージの `settings`（日付変更時刻、週の開始曜日）に従う

## 6. フェーズ計画
1. **基盤**：PWA化、IndexedDB、下りの受け取り（ファイル・文字列）、今日の画面、計測、確認シート、手動記録、上りの送信、acksの処理と7日削除、GitHub Actionsでのデプロイ
2. **入力の拡充**：QRコードの読み取り、誤答の簡易登録、自由記録・未分類、履歴画面、警告バナー
3. **復習**：reviewsの表示と、復習結果の記録

## 7. 受け入れ条件
- `spec/examples/` の下りサンプルを読み込むと、期待どおりに表示される。異常例は拒否され、理由が表示される
- 計測中にリロード、タブを閉じる、画面をロックする、のいずれをしても、再開後の経過時間が正しい
- 上りを送った後、acksを含む下りを受け取ると、該当する記録が「取り込み済み」になる。送信後に編集した記録は未取り込みのまま残る
- acksを受け取らない限り、何日経っても記録が消えない
- 取り込み済みの記録は、7日後に削除される
- 機内モードで起動・計測・記録・ファイル書き出しができる
- iPhoneの幅（390px）で、全画面が横スクロールなしで操作できる
