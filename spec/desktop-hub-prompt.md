# StudyLog 母艦（PC用EXE）制作指示

## 0. 進め方
- 最初に `spec/transfer-spec.md` を読むこと。転送に関わる部分はすべて本書より仕様書を優先する。
- いきなり実装しない。まず**ディレクトリ構成、SQLiteのスキーマ、フェーズ1の実装計画**を提示して承認を得ること。
- フェーズ単位で実装し、各フェーズの最後に受け入れ条件を自己検証して報告すること。
- 不明点は推測で埋めず、質問するか代替案を出すこと。

## 1. 位置づけ
資格試験の勉強記録を一元管理する**母艦**アプリ。唯一の正本（データの原本）を持つ。
- 勉強の記録、集計、計画、目標、苦手分析、合格結果はすべて母艦で行う
- 外出先（図書館など）では、ブラウザ子機に「今日のノルマ」を渡し、子機から勉強時間・メモ・誤答を受け取る
- 今後の機能追加は、原則として母艦に対して行う。子機の変更は最小限にとどめる

## 2. 技術要件
- Python 3.12 / PySide6 / SQLite（標準の `sqlite3`）
- グラフ：QtCharts（PySide6に同梱）を優先する。足りない場合だけ matplotlib を使う
- QRコード生成：`qrcode` ライブラリ
- JSON検証：`jsonschema`（`spec/schemas/` のスキーマを使う）
- 配布：PyInstaller の **onedir** 方式（起動が速く、ウイルス対策ソフトの誤検知も少ないため）。ビルドスクリプトを用意すること
- データの保存場所：`%APPDATA%/StudyLog/`（DB、バックアップ、ログ）。インストール先には書き込まない
- 設計：UIと業務ロジックを分離する（`domain/`、`services/`、`repositories/`、`ui/`）。転送処理は `services/transfer/` に独立させる
- **機能追加への備え**：画面（機能）をモジュール単位で登録する仕組みにし、新しい機能はモジュールを追加するだけでメニューに加わるようにする
- DBのマイグレーション：バージョン番号付きのSQLファイルを順に適用する方式
- テスト：pytest。転送処理、日付計算、集計、復習スケジュールは必ず単体テストを書く

## 3. データモデル（SQLite）
すべてのテーブルに `id`（UUID）、`created_at`、`updated_at`、`deleted_at`（論理削除）を持たせる。
- **exams（資格）**：名称、色、試験日（年度ごとに複数可。`exam_sittings` テーブルで管理）、目標（テキスト＋総勉強時間の目標）、ステータス（学習中／受験済／合格／不合格／中断）、結果（得点、合否、メモ、合格証の受領日）
- **materials（参考書・問題集）**：資格、名称、種別、単位（ページ／問）、総量、現在位置、アーカイブ
- **subjects（分野）**：資格、親分野（2階層まで）、名称、並び順、アーカイブ
- **sessions（勉強記録）**：転送仕様書の `sessions` と同じ項目に加え、`source`（hub／satelliteの端末ID）、`quota_id`
- **plans（勉強予定）**：日付、時刻（任意）、資格、参考書、分野、予定時間、範囲、内容、繰り返しのルール（毎日／曜日指定）
- **quotas（ノルマ）**：子機に渡すために予定から作るもの。`plan_id`、`date`、転送仕様書の `quotas` の項目、達成状況
- **mistakes（誤答）**：転送仕様書の項目に加え、正解・ポイントのメモ、復習の段階、次回復習日、習熟ステータス（未克服／復習中／克服）
- **review_results（復習結果）**
- **tasks（課題）**：資格、分野、内容、期限、優先度、完了
- **weekly_goals（週目標）**：週の開始日、全体の目標、資格別の目標
- **devices（子機）**：deviceId、表示名、最終受信日時
- **transfer_log（転送履歴）**：方向、packageId、日時、件数、結果
- **settings**：日付変更時刻（既定 4:00）、週の開始曜日（既定 月曜）、同期フォルダのパス、復習間隔、つけっぱなし判定の時間など

## 4. 機能要件

### 4.1 計測・記録（PC上での勉強用）
- ストップウォッチ方式のタイマー。経過時間は開始・一時停止の時刻から計算する。計測中の状態をDBに保存し、アプリを再起動しても復帰できること
- 手動での記録、編集、削除
- 前回使った資格・参考書・分野を初期値にする

### 4.2 ダッシュボード
- 今日と今週の勉強時間、週目標に対する進捗、試験日までのカウントダウン
- 今日の予定、今日の復習対象、期限が近い課題
- **未分類の記録の件数**（子機から届いたもの）と、そこから分類画面へ移動するボタン
- 子機ごとの最終受信日時

### 4.3 集計・分析
- 日／週／月ごとの勉強時間グラフ、資格別・参考書別・分野別の内訳、学習日数と連続学習日数
- 分野別の正答率、誤答の件数による苦手分野のランキング、誤答理由の内訳
- 参考書の進捗率
- 予定と実績の比較（ノルマの達成率）

### 4.4 計画・カレンダー
- 月表示と週表示で、予定と実績を重ねて表示する。試験日を強調する
- 繰り返し予定
- 予定からタイマーを開始できる
- .ics の書き出し

### 4.5 ノルマの作成と子機への送信（転送仕様書 第3章・第6章）
- 日付（今日、または任意の範囲）を選ぶと、その日の予定からノルマの案を自動で作る。送る前に追加・編集・並べ替えができること
- 復習対象（次回復習日が当日以前のもの）を含めるかどうかを選べる
- 送信方法：
  - **QRコード表示**：`lite` パッケージ。1,800バイトを超える場合は理由を表示し、ファイルでの送信を案内する
  - **ファイル保存**：`full` パッケージ。同期フォルダの `outbox/` と、任意の場所に保存する
  - **文字列のコピー**：QR用の文字列をクリップボードにコピーする
- `acks` には、取り込み済みの上りパッケージのうち直近30日分のpackageIdを入れる

### 4.6 子機からの取り込み（転送仕様書 第4章）
- 同期フォルダの `inbox/` を監視し（QFileSystemWatcher＋定期的なポーリング）、新しいファイルを自動で取り込む。取り込んだファイルは `processed/` に移動する。検証に失敗したファイルは `rejected/` に移動し、理由を記録する
- 手動でのファイル選択と、ドラッグ＆ドロップでの取り込み
- 取り込み結果を通知する（追加・更新・スキップ・未分類の件数）
- 冪等であること（同じファイルを何度取り込んでも結果が変わらない）
- **未分類の記録の分類画面**：資格・参考書・分野を後から割り当てる。複数件をまとめて割り当てられること

### 4.7 誤答・苦手克服
- 誤答の登録・編集（子機から届いたものには、正解・ポイントのメモを後から追記する）
- 復習スケジュール：正解なら間隔を延ばす（1→3→7→14→30日。設定で変更可）、不正解なら1日に戻す。3回連続で正解したら克服とする
- 母艦での「今日の復習」と、子機からの `reviewResults` の反映

### 4.8 課題・目標・結果
- 課題の管理
- 週目標（未設定の週は前の週の値を引き継ぐ）。資格ごとの総時間の目標と、試験日から逆算した「1日あたり必要な時間」
- 合格の登録時に結果画面（総勉強時間、学習期間、最も時間をかけた分野など）を表示する。合格した資格は実績一覧に残す

### 4.9 バックアップ
- 起動時と終了時に、SQLiteのbackup APIでDBを日付付きで保存する。保持する世代数は設定で決める（既定は14世代）
- 取り込み処理の前にも自動でバックアップする
- バックアップからの復元機能

## 5. 非機能要件
- 起動から3秒以内に操作可能になること
- 1万件の記録があっても、集計画面が1秒以内に表示されること
- 日付の計算（日付変更時刻、週の区切り）は共通のユーティリティにまとめる
- 外部との通信は行わない（ファイルの読み書きだけ）
- ログを `%APPDATA%/StudyLog/logs/` に出力する

## 6. フェーズ計画
1. **基盤**：プロジェクト構成、DB・マイグレーション、マスタ管理、タイマー、記録の一覧と編集、バックアップ、PyInstallerでのビルド
2. **転送**：ノルマの作成、下りパッケージの出力（QR、ファイル、文字列）、上りパッケージの取り込み（監視、手動、冪等性）、未分類の分類画面、転送履歴
3. **可視化**：ダッシュボード、集計・グラフ、週目標、カウントダウン
4. **計画**：カレンダー、繰り返し予定、.ics の書き出し
5. **苦手克服と結果**：誤答、復習スケジュール、課題、苦手分析、資格目標、合格結果

## 7. 受け入れ条件
- 仕様書の `spec/examples/` にあるサンプルが、すべて期待どおりに処理される（正常例は取り込まれ、異常例は拒否される）
- 同じ上りファイルを2回取り込んでも、件数が変わらない
- 母艦で編集した記録が、古い `updatedAt` の上りデータで上書きされない
- 未知のマスタIDを持つ記録が、未分類として取り込まれる
- QR用の文字列が、1,800バイトの上限を超えた場合にファイル送信へ案内される
- 深夜（日付変更時刻より前）の記録が前日に集計される
- ビルドしたEXEを、Pythonが入っていないWindows環境で起動できる
